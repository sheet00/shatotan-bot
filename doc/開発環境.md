# Docker Compose 開発環境

DockerfileでNode公式イメージ `node:latest` にChromiumのOS依存パッケージを追加する。
rootでの準備はイメージビルド時に行い、BOTの実行はホストと同じUID/GIDを使う。
ホストの `src/` をコンテナの `/app` にマウントする。
package関連、コード、データはすべて `src/` 内に置く。

## 起動と依存関係の準備

```bash
mkdir -p src/data/agy-home/.gemini/antigravity-cli
docker compose up -d --build
docker compose logs -f bot
```

起動時にコンテナ内で `npm ci` とChromium本体の準備を行い、`npm start` で内部スケジューラーを起動する。
外部cronは不要。`restart: unless-stopped` により、異常終了やDocker再起動時に復帰する。
インストール、CLI実行、テストはすべてDocker内で行う。
コードや設定を変更したら `docker compose restart bot` で反映する。

## 実行ユーザー

Composeの `user` は `${BOT_UID:-1000}:${BOT_GID:-1000}`。このPCでは `sheet` のUID/GID `1000:1000` と一致する。
依存パッケージや生成データもホストのユーザー所有になり、`chmod 777` は不要。
別のPCでは `id -u`、`id -g` を確認し、プロジェクトルートの `.env` に `BOT_UID` と `BOT_GID` を指定する。
この `.env` はXの認証設定を入れる `src/.env` とは別。
ユーザーやマウント設定、Dockerfileを変更した場合は `docker compose up -d --build` で反映する。

## Antigravity CLIと認証

ローカルPCの次のファイルをマウントする。認証情報はリポジトリへコピーしない。

| ホスト | コンテナ | 用途 |
| --- | --- | --- |
| `~/.local/bin/agy` | `/usr/local/bin/agy` | CLI本体（読み取り専用） |
| `~/.gemini/antigravity-cli/antigravity-oauth-token` | `/app/data/agy-home/.gemini/antigravity-cli/antigravity-oauth-token` | OAuth認証（トークン更新のため書き込み可能） |

ホスト側のパスはComposeを実行するユーザーの `HOME` から解決する。別の場所は `AGY_BIN`、`AGY_AUTH_FILE` で指定できる。
マウント元がない場合は起動に失敗させ、空の認証ディレクトリは作らない。
CLIはホストとコンテナのCPUアーキテクチャが一致するLinux版を使う。
CLIの設定・会話履歴・キャッシュはBOT専用の `src/data/agy-home/` に保存し、ホスト側の設定や履歴は共有しない。
Antigravityの[非対話モード](https://antigravity.google/docs/cli/headless/)で、記事本文を標準入力から渡し、JSON形式の生成結果を受け取る。

## スケジュール設定

`src/config.yaml` で指定する。現在はニュースを毎日9:00〜翌1:00の間、1時間ごとの16枠で各1回実行する。1:00〜9:00は実行しない。
`mode: preview` は生成・保存のみ、`mode: post` は生成後にXへ自動投稿する。
自動投稿には保存済みのXログイン状態 `src/data/x-auth.json` が必要。

以下は設定の抜粋。全16枠は `src/config.yaml` を参照する。

```yaml
timezone: Asia/Tokyo
mode: post
ai:
  provider: antigravity
  timeoutSeconds: 180
news:
  maxAgeHours: 72
  rss:
    - https://news.google.com/rss/topics/CAAqIQgKIhtDQkFTRGdvSUwyMHZNREozWW0wU0FtcGhLQUFQAQ?hl=ja&gl=JP&ceid=JP%3Aja
schedule:
  news:
    - id: news_09
      between: ["09:00", "10:00"]
      count: 1
    - id: news_23
      between: ["23:00", "24:00"]
      count: 1
    - id: news_00
      between: ["00:00", "01:00"]
      count: 1
```

時間帯ごとに一意の `id` を指定する。現在は `count: 1`、日本時間、同日内で重複しない時間帯に対応する。
開始以上・終了未満の時刻を1分単位で抽選し、SQLiteへ保存する。投稿間隔は厳密な60分ではない。
終了時刻の `24:00` に対応する。日跨ぎの時間帯は23:00〜24:00と00:00〜01:00のように分割する。
同じ日・同じidの時刻は再起動や設定変更後も維持する。設定変更は翌日の抽選から反映するため、同日の再実行目的でidを変更しない。
停止中に過ぎた予定、実行中に落ちた予定、失敗した予定は自動再試行しない。
枠の途中で初めて起動した場合は残り時間から抽選する。成功時の投稿数は1件、失敗時は0件となる。
現在の自動処理はニュースのみ。天気処理は今後追加する。

## 手動でニュース投稿文を生成する

```bash
docker compose exec -T bot npm start -- --news
```

RSSグループからランダムにRSSを選び、対象期間内・未投稿の記事候補を重複なく最大10件集める。
候補ID・タイトルだけをAntigravityに渡し、宣伝記事を除外する。残った候補は入力順に扱う。全候補が除外されたら見送る。
Googleニュースのリンク先をChromiumで開いて記事本文を取得し、Antigravityが本文から感想を生成する。本文では宣伝を再判定しない。本文取得・生成に失敗した場合は次の候補へ進み、最大5件まで試す。
本文内の根拠、出力形式、Xの文字数制限を確認して、感想と元の記事URLを表示する。
本文取得や生成に失敗した場合は終了コード1で終了する。有料記事や本文を抽出できないページは見送る。
本文の根拠確認は感想全体の正しさを保証するものではないため、試運転の文面を確認してから自動投稿へ切り替える。

`--news` は設定が `mode: post` でもXへ投稿せず、投稿済みURLや定期実行の枠を消費しない。
定期実行と手動実行は共通のSQLiteロックで同時実行を防ぐ。

今日の抽選時刻と状態を確認する：

```bash
docker compose exec -T bot npm start -- --show-schedule
```

## 動作確認

```bash
docker compose exec bot npm run check
docker compose exec bot npm test
docker compose exec bot npm run smoke
```

`smoke` はヘッドレスのChromium起動とSQLiteの動作を確認する。Xへの投稿は行わない。
自動テストは抽選時刻の永続化・二重実行防止・本文抽出・CLI呼び出しと失敗処理を確認する。
テスト用CLIを使い、AIサービスやXへの投稿は行わない。

## テスト投稿

テスト投稿の文面は「テストだよ☆」。送信には `--send` を明示する。

新しいニュース選定から実際の投稿まで試す場合は `npm run post:news:test -- --send` を使う。`--send` を省略すると生成のみ。保存済みのニュース下書きを使う場合は `--draft data/drafts/<ファイル名>.json` を指定する。コードは `src/tests/news-post-test.ts` に置き、投稿成功時は通常の投稿済み履歴に保存する。

## データと停止

スクリーンショット、ブラウザ本体、SQLiteファイルは `src/data/` に保存する。
コンテナ内の対応先は `/app/data/`。依存パッケージは `src/node_modules/` に置く。
名前付きボリュームは使わない。コンテナを削除してもホストのファイルは保持される。

- `src/data/bot.sqlite`：抽選時刻、実行結果、投稿済みURL、実行ロック。
- `src/data/drafts/`：記事本文、参照URL、生成した投稿文。
- `src/data/log/`：ブラウザの解析ログ。
- `src/data/errors.log`：手動起動時などの失敗記録。定期処理の失敗はSQLiteとDockerログに記録する。
- `src/data/agy-home/`：BOT専用のAntigravityデータ。

```bash
docker compose down
```

Xへの送信後に成功確認や履歴保存に失敗した場合は、再実行前にXとログで投稿の有無を確認する。
